# Database schema

Integer surrogate primary keys identify records; cow identifiers, image paths and standard names have unique constraints. Decimal measurements use fixed precision (12,3); BCS scores use (8,3), confidence (8,6). Timestamps use PostgreSQL `TIMESTAMP WITH TIME ZONE` and UTC application normalization. Calendar birth/registration dates use `DATE`. Text notes are nullable. Created timestamps and updated cow timestamps are populated by the ORM.

| Table | Columns and purpose |
|---|---|
| `cows` | `id`, unique required `cow_identifier`, optional `breed`, `sex`, `birth_date`, `notes`; `registration_date`, `created_at`, `updated_at`. Birth cannot follow registration. |
| `images` | `id`, unique `image_path`, required `captured_at`, `source`, `quality_status`, optional `camera_angle`, `created_at`. No image bytes. |
| `image_cows` | `id`, `image_id` → images, `cow_id` → cows, optional `crop_path`, `segmentation_mask_path`, JSON `bounding_box`, `created_at`. Unique `(image_id,cow_id)` and `(id,cow_id)` for ownership references. |
| `scoring_standards` | `id`, unique `name`, optional `description`, `minimum_score`, `maximum_score`, `approved_by`, `approved_at`; required `created_at`. Approval fields must either both be null (draft) or both present (recorded veterinary approval), enforced by `standard_approval_pair`. Bounds must be ordered. No bundled clinical standards. API `approval_status` is derived, not a database column. |
| `bcs_categories` | `id`, `scoring_standard` → standard name, `category`. Unique `(scoring_standard,category)`. Allowed values are explicitly configured, e.g. Low/Normal/High when approved. |
| `bcs_records` | `id`, `cow_id`, optional `image_cow_id`, optional `bcs_score`, `bcs_category`, required `scoring_standard`, `evaluator`, `evaluation_method`, `evaluation_date`, `review_status`, optional `notes`, `created_at`. Score or category required. Methods manual/veterinary; review pending/approved/rejected. |
| `weight_records` | `id`, `cow_id`, nonnegative `weight_kg`, `measurement_timestamp`, `measurement_context` (before_feeding/after_feeding/routine), `measurement_method`, optional `notes`. No per-day uniqueness restriction. |
| `feeding_records` | `id`, `cow_id`, `feeding_timestamp`, `feed_type`, nonnegative `quantity_offered_kg`, nullable `quantity_consumed_kg`, optional `notes`. Consumed is never inferred, and when supplied must be between zero and offered. |
| `health_records` | `id`, `cow_id`, `observation_date`, `observation_type`, `symptoms_or_observations`, optional `veterinarian_notes`, `follow_up_status`, `created_at`. |
| `milk_production` | `id`, `cow_id`, `measurement_timestamp`, nonnegative `milk_quantity_liters`, `milking_session`, optional `notes`. |
| `ai_predictions` | `id`, `cow_id`, required `image_cow_id`, `model_name`, `model_version`, nullable `predicted_bcs_score`, `predicted_category`, required `scoring_standard`, nullable `confidence_score`, `prediction_timestamp`. At least one predicted label; confidence in [0,1]. |
| `import_rows` | `id`, `resource`, `external_key`, `payload_hash`, `record_id`. Unique `(resource,external_key)` records repeatable import receipts; `record_id` is a polymorphic logical reference managed by importer, not an SQL foreign key. |
| `assessment_workflows` | `id`, `cow_id`, `image_cow_id` (unique association), `scoring_standard`, `mode` (manual/ai), `status` (pending/approved/corrected/rejected), `created_by`, `request_key`, `created_at`; optional unique `bcs_record_id`, unique `prediction_id`, `finalized_by`, `finalized_at`, `review_notes`. Unique `(created_by,request_key)` prevents retry duplication. Composite association/cow FK preserves ownership. Terminal states require finalizer/time; approved/corrected states require a BCS link. Manual workflows cannot reference an AI prediction. |

Workflow records link existing observations rather than duplicating image, prediction or score values. AI-pending workflows do not violate the BCS required-label constraint because they create no BCS row until veterinary review. Workflow correction is an approved BCS label and a separate `corrected` workflow state, preserving existing BCS review enums and export logic. New identity strings are taken from the server credential registry; there is no duplicate users database. Migration `10bc21e4dba4` adds this table only and refuses destructive downgrade while workflow rows exist.

All observation cow references restrict deletion. BCS and prediction `(image_cow_id,cow_id)` reference the same pair in `image_cows`, enforcing identity consistency even outside the API. Both also reference standard/category pairs, so configured categories cannot be mixed across rubrics. BCS image reference is nullable for assessments without a photo. A separate foreign key on standard name ensures even numeric-only labels use a real standard.

Indexes cover image capture time, association cow/image IDs, and `(cow_id,event_timestamp)` on each historical observation table. Unique constraints create their own indexes. Table-level constraints enforce numeric ranges, review/method/context values, required labels, dates and ownership. Application validation additionally enforces timezone awareness, nonblank strings, safe paths, bounding boxes, score bounds and date validity. Score bounds across standard tables are checked by application services rather than a database check constraint; direct SQL writers must apply the same rules. Use the API/import service for writes.

No deletes or cascading historical cleanup are exposed. Cow and BCS PATCH correct values in place; use new assessments for subsequent observations. Detailed revision auditing and authenticated approval workflows are future production work.
